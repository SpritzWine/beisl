Who ate the frame?

Beisl is performance tracing for games on Linux. One line in your launch options; it samples the whole stack with perf, bookmarks the hitches through MangoHud’s frametime log, and hands you the verdict by layer — kernel, GPU driver, the game itself, DXVK, or wine. Any wine. That’s rather the point.

Get beisl Source on Codeberg Launch options: beisl %command%

The headline view

The whole thesis is one bar.

A trace is thousands of stack samples. Beisl buckets every one of them by the layer its module belongs to and answers the only question a stutter really asks: who ate the frame? Not a flamegraph first — a verdict first, with the receipts one click below. And beside every share, an honest number: how much of that layer it could actually name.

The regular’s verdict

“The good pour” is Beisl’s first real capture — Blood West, picked because it runs great: 45% kernel, 32% the game’s own JIT, ~3% DXVK, wine under half a percent. The other two nights and the coverage figures are illustrative. One house rule made this bar possible: brand burgundy never appears in it. The wine segment is the app’s own data red, the driver wears its vendor’s colour — Beislrot frames, layer colours testify.

The side-channel

The hitches, bookmarked.

MangoHud is not the product — it’s the bookmark ribbon. Its frametime log, flushed every frame, timestamps the worst hitches; Beisl turns those timestamps into markers into the perf trace. So instead of staring down a whole-session flamegraph, you jump straight to the five worst hitches and what wine was doing during each.

The frametime log survives up to a crash, and the CSV rides along in the run directory next to perf.data, the logs, and session.json.

Impartial by construction

Any wine. That’s the point.

The capture path never touches a particular wine: the wrapper, MangoHud and perf sample whatever runs — stock Proton, GE, Lutris-wine, system wine, SpritzWine, even a native Linux game. Which makes Beisl an impartial critic: it can trace the baseline half of an A/B (“same game, same driver, different runtime”) just as happily as the house’s own pour.

Symbol fidelity is tiered instead of assumed — and every trace is stamped with its tier, so a comparison never silently reads full symbols against partial ones.

The house stance

“Confirming a good game is good is a first-class result, not a null one.”

Beisl is the honest regular, not a doom tool. It says so with conviction when it wasn’t the wine — which is exactly why you can trust it when it says it was. Good runs are a result too.

How it works

Launch option in, verdict out.

  1. Pour

    Put beisl %command% in the game’s Steam launch options — or set it as the Lutris wrapper, or run beisl wine game.exe. No game patching, no ptrace: PMU sampling, so even anti-tamper titles tolerate it.

  2. Play

    Beisl sets the table: MangoHud logs frametimes every frame, perf records the stack, and everything — trace, logs, CSV, session.json — lands in a per-run directory under ~/.local/share/beisl/traces/.

  3. The verdict

    A crash is analyzed on the spot. A clean run is kept and politely asked about: Analyze or Discard — your trace, your call. Analysis yields the layer bar, the frametime timeline, and the issues panel.

The wrapper beisl %command% · beisl check — the CLI that runs the show and vets your host: perf, symbolizer, paranoid level, MangoHud, GPU quirks like dual ICDs.
The headless verdict beisl symbols <run-dir> — the same layer split as a text bar, plus artifact.json and report.txt you can hand to anyone. Or to a machine: an MCP server is on the roadmap.
The session window beisl-setup — preflight checklist with guided fixes, then the results view: the vendor-coloured layer bar, frametime chart with spike bookmarks, and which debuginfo would sharpen the picture.

Quickstart

On tap in two minutes.

  • Steam beisl %command% in Launch Options
  • Lutris beisl as the wrapper / pre-launch command
  • Bare wine beisl wine game.exe
  • SpritzWine a “Record performance” toggle in the control panel — no launch options at all

Beisl is young — a working v0 engine with the GUI results view landing in v1. The Exports symbol tier is built and proven on real captures; Full-tier symbols and the MCP server are en route. Source, issues and releases: codeberg.org/SpritzWine/beisl (placeholder — point at the real repo). 

# from an extracted release bundle:
./beisl install   # beisl + beisl-setup onto your PATH

# once: vet the host (perf, llvm, paranoid, MangoHud, GPU)
beisl check

# Steam → your game → Properties… → Launch Options:
beisl %command%

# next launch is traced; each run keeps its own dir:
#   ~/.local/share/beisl/traces/run-*/
